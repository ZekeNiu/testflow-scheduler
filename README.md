# TestFlow 测试排程与耗时计算器

用于多站点测试的现场组织、等待分析与完整方案比较。

在线使用：https://zekeniu.github.io/testflow-scheduler/

直接打开 index.html 也可离线使用。页面没有外部脚本依赖，方案保存在当前浏览器，也可将方案与优化条件保存为 JSON。

## 使用方式

在方案设置侧栏填写人数、测试站点、完整耗时、容量、复位、离站间隔、休息与到场要求。
站点时间轴、人员时间轴、排程明细、到场安排继续随当前方案更新。

进入统一的“方案优化”，选择目标与允许调整的组织方式。默认不增配；需要容量调整时，填写各站实际可用上限。
自动比较会评估组织方式和多个站点容量的完整组合；同页可展开手动试算，微调一个或多个站点。
所有结果相对当前方案，列出收益、不利变化与共同的上限检查。只有预览、核实规程并确认后才应用，可撤回本次完整调整。
主目标没有明显改善时默认保留当前方案；若存在显著减少等待等收益，会直接展示辅助方案和增加到场组织等代价。

## 功能

- 可收起的方案设置侧栏，四张结果卡片可自行选择指标。
- 个人流水线、全员逐站完成、分组同步轮转；独立工位与整批测试分别建模。
- 指定站点或轮次全体完成后统一休息，完整测试不被拆开。
- 自动分批到场，按首站开测安排就位及提前准备。
- 站点与人员时间轴，鼠标悬浮或键盘查看具体时刻的测试、工位、等待人员。
- 站点工作时长、工位使用率、平均与最长等待、峰值等待人数。
- 统一方案优化：容量边界、联合搜索、手动向量试算、完整对比、耗时延长情景、确认与撤回。
- 核对人均累计等待、最长单站等待、最长个人累计等待、峰值等待、峰值在场、开场至收尾时长及到场波次数上限。
- 同一建议到场时刻计为一个波次，另列接待分组；展示最早到场、收尾结束和场地覆盖时长。
- 耗时延长可选择重新规划到场，或保持各方案已经通知的到场表，观察执行中的等待变化。
- 带样式的 XLSX 排程总览、人员排程、站点排程、到场安排四表，兼容 CSV 和 JSON 保存/载入。

## 科学边界

时间精度最多三位小数秒。等待从个人满足最低离站间隔或首站本批就位时算起，包含排队、凑批、统一换站，扣除整体休息。
人均累计等待先把每人的各站等待相加，再除以人数；全场峰值等待按同一时刻的不同人员计算，各站峰值不能相加。
最长单站等待与最长个人累计等待是不同口径。P90 使用最邻近秩，详见优化页面指标说明。

在场指标按建议到场至本人最后测完计算，假定本人可立即离场，不含工作人员与之后统一收尾。
分批到场不必然缩短全场测试。工位使用率也不能单独证明某站容量不足。

优化不改变测试内容、时长、复位、必要离站恢复、开批规则及休息。
按各站资源独立、固定耗时、准时执行建模；共享操作员、跨站共用设备及个体疲劳尚未建模。
已知共享资源时暂停推荐与应用。耗时延长情景是用户设定的假设，不是准时完成概率。
普通参数编辑不会清除已知共享状态，只有明确修改资源声明才能解除阻断。
开场至收尾时长从开场算起；场地覆盖时长从开场与最早到场两者中的较早时刻算起。
初始运动测试方案仅为演示，测试顺序、耗时及必要恢复须按具体规程核实。

完整覆盖声明范围才称范围内最优；默认最多计算 600 个配置，允许设置至 3000，限量结果仅称已找到的较佳方案。
搜索先探测当前组织方式下各站单站及允许的双站增配，再扩展组织组合；任意预算不能保证覆盖所有容量值。
没有成本数据时不评价最经济。默认提醒阈值不是运动测试标准；未设置等待上限不等于等待合理。
通过计算回归和浏览器检查不能证明真实现场预测准确，仍需到场、开始、结束、复位和转场记录校准。

## 开发与验证

模块在 src/，build.py 生成单文件 index.html。最多支持 500 人、20 个站点、20 段整体休息。

```bash
npm test
python3 build.py
python3 tests/unified-browser.py
python3 tests/auto-advice-browser.py
python3 tests/review-browser.py
python3 tests/export-regressions.py
```

构建只需 Python 3，计算回归只需 Node.js 18 或更新版本，无需 npm 依赖。
浏览器验证需要 Playwright 1.57.0 与 Chromium；导出验证另需 openpyxl 3.1.5。CI 使用真实 localStorage 并保存多尺寸截图。
旧浏览器测试命令转发至统一套件，不再维护独立容量页签的过时断言。

详细设计、指标、限制和回退说明见 [docs/plan-optimizer.md](docs/plan-optimizer.md)。
本次审查优化的验收范围见 [docs/review-improvements.md](docs/review-improvements.md)。旧版本验证记录保留在 docs 中，其哈希不代表本次修改。

原排程、持久化及导出引擎保持兼容，现有 version:4 方案不做破坏性迁移。
JSON 可选 optimizerContext.version:1 保存目标、上限、搜索边界和资源声明。载入旧文件沿用本机目标与上限；载入新备份保留已知共享阻断，资源独立性须现场重新核实。
