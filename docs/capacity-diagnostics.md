# 容量瓶颈预警

## 界面与判断

全局容量建议链接到“站点运行与排队情况”的内嵌预警。站点名称旁的标签可查看判断依据；预警可定位时间轴或进入对应容量试算行。试算不自动改动方案，应用后仍可撤回。

所有启用且容量小于本次人数的站点分别增加 1 人容量，完整重算总时长、人均累计等待及全场峰值等待。复用原有排程引擎，支持独立工位、整批测试、三种排程模式、到场安排和休息。

- 扩容可提速：该次试算缩短总时长；同等最高提速收益的站点均保留优先提示。
- 可减少等待 / 可降低峰值：总时长不变，对应等待指标改善；其他指标变差时明确提示取舍。
- 等待关注：人均本站等待最高但试算未确认改善，不等于本站容量不足。

自动分批到场会随容量重算；各站单独试算收益不可相加。单站 +1 无收益不代表不存在共同瓶颈。整批测试增加的是每批人数上限，不是新增并行设备。数字按既有毫秒精度计算，基于固定耗时和准时执行，不是现场实时监测。

## 维护

`src/testflow-diagnostics.js` 是独立、可测试的诊断模块。`src/testflow-capacity-ui.js` 由 `build.py` 在 UI 首次渲染前装入同一闭包，沿用现有持久化扩展方式；构建会校验唯一初始化锚点，避免上游结构改变后静默失效。原始排程、数据格式、持久化与导出逻辑未改动。缓存仅保存一个配置的紧凑试算指标，不保存多份人员排程。

运行 `npm test` 和 `python3 build.py`。可选 UI 测试：安装 Playwright 与 Chromium 后运行 `python3 tests/capacity-browser.py`；可通过 `TESTFLOW_CHROMIUM` 指定浏览器。该测试离线渲染完整页面，使用内存存储 fixture，不替代真实磁盘持久化测试。
