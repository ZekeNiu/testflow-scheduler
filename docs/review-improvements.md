## 已实现行为

| 审查问题 | 实施后的行为 | 回归入口 |
|---|---|---|
| 隐藏到场参数导致缓存错配 | 报告绑定完整计算快照；确认窗口与应用均重新计算并核对上限 | review-regressions / review-browser |
| 普通编辑清除共享约束 | 已知共享持续阻断；编辑、刷新、撤回和载入备份不能悄悄解除 | review-browser |
| 自动分组手动入口失败 | 手动起点使用引擎的有效组织方式、组数与到场方式 | review-regressions / review-browser |
| 到场分组误当分时次数 | 同一毫秒到场时刻计一波；接待组另列，指标、上限、CSV 与 XLSX 一致 | arrivals / review-regressions / export-regressions |
| 双站探测被前排配置耗尽预算 | 当前组织方式的单站、双站 +1 优先于扩展组织；20 站反例默认 600 次触及最后两站联合调整 | review-regressions |
| 主目标不变掩盖减少等待 | 默认保留当前，同时显示辅助方案的收益、全部不利变化和完整比较入口 | review-browser |
| 开场时长遗漏提前接待 | 另列最早到场与场地覆盖时长；默认总时长卡片说明覆盖窗口 | review-regressions / review-browser / export-regressions |
| 等待人数不能代表拥挤 | 可选峰值在场人数硬上限，空白与零分别表示未评价与严格零上限 | review-regressions / review-browser |
| 耗时情景同步重排通知 | 保留重新规划，增加固定各方案原通知表的执行情景 | review-regressions / review-browser |
| JSON 缺少优化条件 | 可选版本化上下文；旧文件兼容；非法条件载入前整体拒绝，独立资源需重新核实 | review-browser |
| Excel 本地钟面时差错误 | 时长公式使用相对秒数，本地日期用于显示 | export-regressions / native-excel |

默认仍保持现有容量，不擅自允许不同起始站点；未设上限不评价该项是否合理。满批规则明确为“满批优先，尾批可不足”，示例标明为演示参数。

## 可复核反例

- 20 人、两站各 120 秒，自动到场提前准备 300→600 秒后切回集中到场，候选预览及应用应共同显示人均在场 **840 秒、峰值 7 人**。
- 两站轮转、组数留空，手动把两站容量改为 2，应正常得到 **1200 秒**；集中到场的两组应为 **1 波、2 接待组**。
- 40 人、20 站，前 18 站各 1 秒、最后两站各 120 秒，只允许最多两站容量 1→2：默认预算应比较最后两站联合增配，得到 **3940 秒**，满足 4000 秒上限。8440 个声明配置未完整覆盖，仍不得称范围内最优。
- 20 人、两站各 120 秒，总时长 **2520 秒**不变时，展示人均等待 **1140→0 秒**、峰值等待 **19→0 人**，以及到场波次 **1→20**的代价；默认保留当前方案。
- 3 人、单站每人 60 秒，原通知到场 0/60/120 秒；耗时延长 50%：重新规划等待为零，固定原通知人均等待应为 **30 秒**。
- 单人 10 秒、提前准备 300 秒、无其他准备收尾：开场至收尾 **10 秒**，最早到场 **−300 秒**，场地覆盖 **310 秒**。

## 验证入口与边界

`npm test` 执行八份计算及自动建议套件，包含本次 11 项反例。`python build.py` 生成页面；统一工作台与自动建议浏览器套件保留既有功能回归。`tests/review-browser.py` 使用真实本机 HTTP、隔离浏览器上下文、实际输入、保存、应用与撤回核验新增流程。

`tests/export-regressions.py` 实际生成 10 个工作簿，检查压缩完整性、四表结构、筛选、冻结表头、样式、缓存值与独立公式重算。场景包括纽约春秋夏令时、上海、1900 年日期边界、无日期、毫秒、集中轮转和尾批。

在安装 Microsoft Excel 的 Windows 环境，可运行：

```powershell
python tests/export-regressions.py --output-dir test-results/xlsx
pwsh -File tests/native-excel.ps1 -FixtureDirectory test-results/xlsx -ReportPath test-results/native-excel.json
```

本次本机 Excel 16.0 已真实打开并完整重算 10 份工作簿，60 个关键单元格均符合引擎结果。结果文件与最终构建哈希记录在 `docs/review-verification.json`。旧版本的验证 JSON 保留历史含义，不代表本次源码。

对已复现问题的修复判断为**高置信度**，依据为计算反例、真实浏览器操作与导出重算。真实现场预测准确度仍为**未知**：尚无预测与实际对照记录。耗时情景是确定性假设，没有随机分布或成功概率；共享资源、个体疲劳、随机迟到及工作人员占用尚未建模。尚未覆盖全部浏览器、真实移动设备及现场执行。
