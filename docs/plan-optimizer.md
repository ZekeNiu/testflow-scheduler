# 方案优化与条件预警

## 界面分工

站点运行表只显示原有九列事实数据，不再放置“可缩短总时长”等重复标签。
“排程结果”标题旁提供“自动优化方案”入口；结果页签新增“方案优化”，位于“容量试算”前。
方案优化保持现有资源，容量试算评估调整人数上限，两者不混用参照。
沿用现有字体、表单、卡片、按钮、细边框、配色和关闭控件，不增加左侧强调条。

一个站点表示一项每位受试者都要完成的完整测试及其所需资源。多台同类设备通常通过
“可同时测试人数”表达，不能误录成要求每人再做一次的新测试。测试名称和人数不足以
确定最优排程，因此复用已填写的完整测试耗时、复位、离站间隔、开批规则和人数上限。
共享操作员、跨站共享设备、个体差异和疲劳效应未建模，组织方式仍需由操作者核实。

## 比较和应用

目标可选现场总时长、人均累计等待时间或全场峰值等待人数。
默认只比较个人流水线与全员逐站完成，保持当前到场方式，不默认允许不同起始测试。
明确允许轮转后，比较全部有效组数；允许到场调整后，比较集中与自动分批到场。
当前方案始终纳入比较。候选只修改 mode、groups、arrivalMode，不改变站点列表顺序、
人数上限、测试时长、复位、离站间隔、开批规则、整体休息、准备、收尾和机动时间。
已有整体休息时，不跨越按轮次与按站点顺序休息的模式边界，以保留休息位置的含义。

最多枚举 44 个声明范围内的配置。全部成功计算后才能称“本次比较范围内最优”。
先满足已设上限，再按目标排序；同等结果优先保留当前方案。
时间目标依次比较总时长、平均等待、峰值人数、最长等待；平均等待目标依次比较
平均等待、总时长、峰值人数、最长等待；峰值目标依次比较峰值人数、平均等待、总时长、最长等待。
不声称任意调度空间的全局最优，不搜索任意站点排列、人员排列、自由到场时刻或设备增配。

对比完整方案的总时长、平均等待、最长单站等待、峰值等待和到场批次数。
不利影响明确披露，不将不同方案的单项最优值拼接。应用前需确认，可撤回本次调整；
之后实际方案编辑会使旧撤回入口失效，避免覆盖后续修改。
方案或比较条件变化使旧结果失效，不应用过期建议。
比较在内嵌 Web Worker 中执行，可停止；没有 Worker 支持时采用分段计算。
保持单 HTML 离线分发，不新增网络服务。

## 何时预警

可接受上限均为可选：人均累计等待、最长单站等待、峰值等待人数、现场总时长。
留空表示未定义标准，零表示严格零上限。

设置上限后，任一超出即提示核查；全部已设上限满足时不自动预警，但保留可选优化建议。
未设置上限时，仅明显改善机会触发预警：时间改善同时达到绝对量（默认 60 秒）和
相对当前值比例（默认 5%）；峰值人数改善同时达到人数（默认 2 人）和相同比例。
这些是可以修改的界面提醒阈值，不是运动测试或健康标准。
不再因某站等待排名最高或仅有极小收益就始终报警。

接近范围内最优只说明改善空间小，不代表等待已可接受；即使已经最优，超出已设上限仍提示。
没有可行方案时明确说明，不擅自放宽标准。未设置上限时不宣称“等待合理”。
容量增配机会与现有资源下的组织优化分别判断；单站收益不可相加，不排除共同瓶颈。

保留按实际方案签名独立关闭及持久化。刷新、切换视图、缩放、修改优化偏好和未应用试算，
都不重新打开已关闭的预警。实际方案变化后重新判断，只有触发条件成立才显示。
关闭后查看详情使用对话框，不恢复页面预警。

## 测试和维护

独立计算模块：src/testflow-optimizer.js。
界面扩展：src/testflow-optimizer-ui.js，在既有容量扩展之后、第一次渲染之前安装。
该扩展接管站点表与条件预警渲染，旧容量模块中的表格标签渲染不再执行。
原始排程引擎、方案数据格式、持久化和导出代码保持不变。

运行 npm test、node tests/optimizer.cjs、python3 build.py。
浏览器检查包括 tests/capacity-browser.py、tests/capacity-preferences.py、tests/optimizer-browser.py。
CI 用 TESTFLOW_REAL_STORAGE=1 验证真实浏览器存储；离线受限环境明确使用内存 fixture。
新增数值测试包含 90 个独立穷举对照，以及范围、零上限、失败候选、取消和 500 人 / 20 站压力测试。
