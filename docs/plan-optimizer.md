# 统一方案优化工作台

## 使用流程

“方案优化”和“容量试算”合并为一个结果页签。人数、站点、测试参数仍只在原方案设置侧栏录入。
本页按“当前基准 → 优化目标与调整边界 → 完整方案比较 → 预览确认 → 应用或撤回”组织。
默认保持当前容量；开启容量调整后，填写各站实际可用上限。默认上限等于当前值，不假定存在额外设备。
手动容量试算是同页的可展开工具：同时修改一个或多个站点，计算一次完整方案，不逐行直接应用。
可以把自动候选的组织方式载入手动试算，继续微调容量。

每个自动或手动方案都相对当前实际方案比较，不把单站收益相加，不将不同方案的单项最优值拼接。
试算不写入实际方案，导出始终对应已应用的当前方案。应用前展示完整对比，并要求确认资源与测试规程。
应用一次性改变全部已列出的组织方式和容量；撤回恢复应用前的完整方案。实际方案被继续编辑后，旧撤回失效。

## 优化范围及约束

保留测试人数、启用测试、站点列表顺序、完整耗时、复位时间、离站恢复、开批规则、整体休息、准备、收尾与机动。
只比较明确允许的组织方式、轮转组数、到场方式与各站容量范围。轮转沿用既定均分与起点分配规则，不搜索任意个人调度。
已有整体休息时，不跨越按站点与按轮次的语义边界。
独立工位的容量是可同时测试人数；整批测试的容量是每批人数上限，不是新增并行设备数量。

容量自动搜索区间为当前值至用户填写的可用上限，可限制最多改变几个站点。
手动试算也使用同样可用上限与站点数限制，并允许减少容量。
所有容量向量都会与允许的组织配置共同计算；共同限制的站点不会因单独增配无总时长收益而被剔除。
默认最多比较 600 个配置，可设置 1–3000；当前方案优先纳入。
大范围先保留当前组织方式与容量，覆盖各站单站 +1、允许的双站 +1 及全站联合 +1 探测，再扩展组织方式与其他容量值。达到计算上限后不声称整个声明范围最优。
完整覆盖声明范围且所有配置成功计算，才能使用“范围内最优”；否则仅提供已找到的较佳方案。
限量搜索没有达标结果不证明无可行方案。未完成或计算失败时不会提供最优性结论。

先检查用户上限，再按目标和既定次级指标排序，同等结果减少改动。
严格数值领先结果与建议采用结果分开；当前方案满足已设上限、目标改善未同时达到绝对与相对阈值时，默认保留当前方案。
60 秒、5% 与 2 人是可修改的产品设置，不是运动测试标准。
结果保留少量有区别的完整方案，展示所有不利变化；没有资源价格或人员成本输入，不声称“最经济”。
主目标未达到改善阈值时仍默认保留当前方案，但会直接展示显著的次级收益、组织代价及完整辅助方案入口。

## 现场适用性

本模型假设各站资源独立、固定耗时、准时执行。跨站共享设备、共享操作员、个体恢复差异和疲劳效应未建模。
资源尚未核实时可以查看模型试算，但应用前必须明确核实。
用户选择“存在跨站共享资源”时，暂停本页推荐、手动比较和应用，避免假装已解决资源占用冲突。
人数、名称、耗时等普通编辑不会清除这一共享声明；只有用户明确修改资源状态才能解除阻断。
系统不会为了获得更短预计时间，自动减少必要测试、恢复或整体休息。

## 指标与上限

共同检查：开场至收尾时长、人均累计等待、最长单站等待、峰值等待人数、峰值在场人数、最长个人累计等待、到场波次数。
空白表示未定义，零是严格零上限。手动试算允许显示未达标结果，但不提供推荐应用，也不自动放宽限制。

个人累计等待是该人的各站等待之和；最长单站等待是一人一次等待的最大值，二者不能混用。
P90 采用最邻近秩：个人累计等待升序，第 ceil(0.9×人数) 个数值。
等待不计提前准备、最低离站间隔和整体休息。
在场时长从建议到场到本人最后一次测试结束，假定完成后可离场，不含后续统一收尾。
峰值在场人数只计参与作业人员，包含准备、测试、恢复、等待与休息，不含工作人员，不等于峰值等待人数。
自动分批到场反推既定首站开测时间，减少首站等待，不保证缩短整场结束时间；到场波次数也需考虑组织负担。
波次按相同毫秒到场时刻合并；集中到场始终为一波，同时抵达的轮转小组保留为独立接待组。
开场至收尾时长从开场算起；场地覆盖时长从开场与最早到场两者中的较早时刻算起，终点为收尾结束。
“满批优先，尾批可不足”允许最后一批不足容量；严格满批或最低开批量未建模。

耗时波动情景把两份完整方案的各站完整耗时同时延长指定比例，复位、恢复与休息不变。
默认“重新规划到场”会随延长后的耗时重新生成到场表；“保持已通知到场表”冻结当前与候选各自的原始到场及首站就位安排，重新计算等待和延误。两份方案的原表可能不同，比较仍以各自方案为单位。
不模拟随机迟到与耗时分布，不提供成功概率。
情景结果不影响正式耗时，不会被确认应用。

## 提示、样式与兼容

只保留一个“方案检查与调整建议”卡片，区分超限、已设项目达标与未定义标准。
未设等待标准不能被解释成等待合理；时间超限也不自动归因为某站容量不足。
沿用现有字体、色彩变量、按钮、表单、细边框和关闭控件，不增加左侧强调条。
站点运行表保持九列事实数据，不恢复重复建议标签。表格在窄屏容器内横向滚动，不撑宽整个页面。
关闭状态按实际方案保留；刷新、视图切换、优化偏好或未应用试算不会重新打开。
真实有效方案变化后重新判断；无效输入恢复为原方案不应改变关闭状态。

实际方案沿用 version:4 与 testflow-plan-v2，继续兼容 version:2/3/4 旧 JSON。CSV 追加接待组编号并将到场计数明确为波次；XLSX 保留四表和样式，增加覆盖窗口并明确计划时间。
JSON 可选 optimizerContext.version:1 保存优化目标、全部上限、容量与搜索边界、资源声明。非法上下文在载入前整体拒绝；旧文件沿用本机目标及上限，新文件恢复条件后把独立资源声明降为尚未核实，已知共享保持阻断。
Excel 时长公式使用排程相对时间差，钟面日期仅用于展示，避免跨夏令时跳变导致时长复算错误。
优化偏好使用 testflow-optimizer-preferences-v2；只读迁移 v1 偏好，不删除或覆盖旧键。
容量范围按当前实际方案绑定；方案变化后失效并重置为当前值，避免站点索引在删除、启停、排序后误配。
不清空浏览器现有方案。代码版本回退与页面的方案撤回是两套机制。

## 开发与验证

核心计算 src/testflow-optimizer.js；界面 src/testflow-optimizer-ui.js；样式 src/testflow-optimizer.css。
构建仍生成无外部脚本依赖的单个 index.html。
搜索、手动试算与情景计算共用内嵌 Worker；无 Worker 时使用回退路径。搜索可取消，旧结果不可应用。
自动、手动、缓存、预览及应用绑定完整计算输入快照，包含当前模式隐藏、候选可能使用的参数；预览和应用均重新计算并核对上限。格式、卡片等显示偏好不属于计算输入。

运行：

```bash
npm test
python3 build.py
python3 tests/unified-browser.py
python3 tests/auto-advice-browser.py
python3 tests/review-browser.py
python3 tests/export-regressions.py
```

浏览器套件需要 Playwright 与 Chromium。旧三份浏览器检查入口转发到统一套件，避免保留已删除页签的断言。
CI 集中在 .github/workflows/test-unified.yml，记录真实浏览器保存、计算回归、端到端检查、截图及源码/生成页面哈希。
预发布证据见 docs/unified-verification.json。历史测试和旧行为可在备份分支查阅。
